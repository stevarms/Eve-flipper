# LP Store Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A new LP Store tab that ranks every offer in a loyalty-point store by ISK/LP (instant sell, listed sell, blueprint-copy sale, build-and-sell) and lets the user assemble a redemption basket that copies as one Jita multibuy.

**Architecture:** A pure calculator in `internal/engine/lp_store.go` turns offers + prices + industry results into rows. `internal/api/lp_store.go` fetches offers (ESI), order books (via the industry analyzer's loaders), contracts, and runs the industry analyzer per blueprint offer, streaming NDJSON in phases. The frontend tab reads the Profitable Blueprints scanner's saved settings and does basket maths client-side in a small tested module.

**Tech Stack:** Go 1.26 (`net/http` 1.22+ mux, modernc SQLite), React 19 + TypeScript + Vite + Tailwind, vitest.

**Spec:** `docs/superpowers/specs/2026-09-23-lp-store-design.md`

## Global Constraints

- Every locale key exists in both `frontend/src/lib/locale/en.ts` and `ru.ts`.
- Every POST `/api/...` route is classified in `hostedQuotaFeatureForRequest`; `POST /api/lp/analyze` → `"scans"`.
- NDJSON writes go through one mutex (`writeMu` pattern) and short-circuit on `ctx.Done()`.
- Each concurrent industry analysis uses its own shallow copy of `IndustryAnalyzer`.
- Industry analysis for LP blueprints: `ME = 0`, `TE = 0`, `Runs = offer.quantity`, `OwnBlueprint = true`.
- A blueprint offer's `quantity` is runs on one copy.
- Unpriced required item → the offer's values are null, never costed at zero.
- `bpc_sale` has no broker fee or sales tax.
- Scope `esi-characters.read_loyalty.v1` added to both `main.go` and `main_wails.go`.
- Don't touch `assets/badges/*`.

## Review Focus

1. A required item with no sell orders (e.g. a rare tag): the row must read "?" and sort last, not show an inflated ISK/LP. → Task 1 test `TestLPUnpricedRequiredItem`.
2. An offer with `lp_cost == 0` (a few stores have ISK-only offers): no divide-by-zero / Inf in JSON. → Task 1 test `TestLPZeroLPCost`.
3. Contract with a multi-run BPC and a price of 0 or a bundle of several items: must not enter the median. → Task 1 test `TestLPBPCMedianFiltersContracts`.
4. Stream consumer disconnects mid-scan: workers must not write to a closed writer. → Task 4 (ctx check in `writeLine`, same as the blueprint scanner).
5. Basket with the same required item from several offers and build materials overlapping it (e.g. Tritanium): merged into one line. → Task 6 test "merges required items and build materials by type".
