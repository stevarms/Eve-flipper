# `components/ui/` — primitives

shadcn/ui-**shaped** primitives: same component APIs, same Radix underpinnings,
same `cn()` composition. Deliberately **not** generated by `shadcn init`.

## Why hand-written

`shadcn init` installs its own CSS variable system (`--background`,
`--foreground`, `--primary`, `--muted`, …) and rewrites `tailwind.config.ts` to
match. This app already has two established colour systems:

1. `--eve-*` — six faction palettes × light/dark, driving all existing markup.
2. The semantic layer added in phase 0 (`--sem-profit`, `--text-*`,
   `--surface-*`, `--sec-*`).

Adding shadcn's defaults would make a third, conflicting vocabulary, and its
neutral greys would fight the faction accents rather than follow them. So the
components are written by hand against the tokens this app actually has.

## Consequence

`pnpm dlx shadcn add <component>` will **not** produce something that matches
these. When you need a new primitive, copy the upstream source for structure and
then bind it to our tokens — surfaces via `bg-surface-*`, text via `text-fg*`,
state via `text-profit` / `text-loss` / `text-warn` / `text-info`, accent via
the existing `eve-accent`.

See `docs/UI_DESIGN_SYSTEM.md` for the full token contract.
